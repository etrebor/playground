bmi330.py - BMI330 IMU readout over spidev
==========================================

Resets and configures the Bosch BMI330 on the QSXP-ML81 carrier, then
prints accelerometer, gyroscope, temperature and sensor time to the
terminal.


REQUIREMENTS
------------
On target:
  python3, python3-spidev
  /dev/spidev1.0 present (ECSPI1, see HARDWARE / BUILD below)

Run as root.


INSTALL
-------
  scp -O bmi330.py root@<board-ip>:/mnt/userfs/

-O is needed because dropbear has no SFTP server. Reflashing userfs
wipes /mnt/userfs; copy the script back afterwards.


USAGE
-----
  python3 bmi330.py [options]

  --bus N          spidev bus            (default 1)
  --cs N           spidev chip select    (default 0)
  --speed HZ       SPI clock             (default 1000000; DT max 10 MHz)
  --odr HZ         sensor output data rate: 12.5 25 50 100 200 400 800
                                         (default 100)
  --acc-range G    2 4 8 16              (default 8)
  --gyr-range DPS  125 250 500 1000 2000 (default 2000)
  --rate HZ        print rate            (default 10)
  --count N        lines to print, 0 = until Ctrl-C (default 0)
  --raw            print raw counts instead of units

Examples:
  python3 bmi330.py
  python3 bmi330.py --rate 50 --count 200
  python3 bmi330.py --acc-range 2 --gyr-range 250
  python3 bmi330.py --raw


WHAT THE SCRIPT DOES
--------------------
1. Dummy read (CS rising edge switches the BMI330 from I2C to SPI mode).
2. Reads CHIP_ID; exits unless the low byte is 0x48.
3. Soft reset (0xDEAF to CMD 0x7E), 5 ms wait, dummy read again.
4. Prints STATUS and ERR_REG after reset.
5. Writes ACC_CONF and GYR_CONF (normal mode, chosen range and ODR),
   waits 50 ms for gyro start-up, reads both back and checks ERR_REG.
6. Loops: one 9-register burst from 0x03 (acc XYZ, gyr XYZ, temp,
   sensor time), converted and printed.


EXPECTED OUTPUT (board flat and still)
--------------------------------------
  Accel   about +1.000 g on the axis pointing up, ~0 on the others.
          |a| (magnitude) close to 1.000 in any orientation.
          Tilting moves the 1 g between axes; |a| stays near 1.
  Gyro    near 0 deg/s (within about a degree). Rotating the board
          makes the matching axis jump.
  Temp    a few degrees above ambient (die self-heating).
  t s     sensor's own clock (39.0625 us/LSB), increasing steadily.
          If it stalls, the sensor is not running.

"(no valid sample yet)" means a data register still holds 0x8000,
normal for the first read or two after configuring.


SPI PROTOCOL (BMI3xx)
---------------------
Read:
  byte 1  MOSI 0x80 | reg     MISO ignore
  byte 2  MOSI 0x00           MISO dummy byte - ignore (fixed protocol
                                   slot, not a timing delay)
  byte 3  MOSI 0x00           MISO register LOW byte  (bits 7:0)
  byte 4  MOSI 0x00           MISO register HIGH byte (bits 15:8)
  ...keep clocking: address auto-increments, next register lo, hi, ...

  value = rx[2] | (rx[3] << 8)        (little-endian)

Write:
  reg & 0x7F, data low byte, data high byte   (no dummy byte)

SPI mode 0 or 3. Interface starts in I2C mode after power-up and after
soft reset; the first CS rising edge switches it to SPI.


REGISTERS USED
--------------
  0x00 CHIP_ID   low byte 0x48 = BMI330 (BMI323 reads 0x43).
                 High byte is reserved and may be nonzero
                 (this board reads 0x1248) - always mask with & 0xFF.
  0x01 ERR_REG   bit 5 accel config error, bit 6 gyro config error
  0x02 STATUS    bit 0 power-on detected (0x0001 on an unconfigured
                 part, as seen on this board)
  0x03-0x05      ACC X/Y/Z      signed 16-bit
  0x06-0x08      GYR X/Y/Z      signed 16-bit
  0x09           TEMP           degC = raw / 512 + 23
  0x0A-0x0B      SENSOR_TIME    32-bit, 39.0625 us per LSB
  0x20 ACC_CONF  [14:12] mode (4 = normal), [6:4] range, [3:0] ODR
  0x21 GYR_CONF  same layout
  0x7E CMD       0xDEAF = soft reset

Range codes  accel: 0=2g 1=4g 2=8g 3=16g
             gyro:  0=125 1=250 2=500 3=1000 4=2000 deg/s
ODR codes    0x5=12.5 0x6=25 0x7=50 0x8=100 0x9=200 0xA=400 0xB=800 Hz
Scaling      accel g = raw * range_g / 32768
             gyro dps = raw * range_dps / 32768

The register map is taken from the BMI3xx family (shared with BMI323).
Chip ID and STATUS reads on this board match it. If the script reports
a readback mismatch or nonzero ERR_REG, check the ACC_CONF / GYR_CONF
field definitions against your BMI330 datasheet revision.


TROUBLESHOOTING
---------------
  CHIP_ID wrong / 0xFF / 0x00   check bus number (1, not 0), wiring, CS
  readback mismatch             writes not landing - check MOSI
  ERR_REG nonzero               invalid ACC_CONF/GYR_CONF combination
  all zeros or 0x8000           sensor not in normal mode; see readback
  /dev/spidev1.0 missing        DT node not in the booted DTB, or old
                                bootfs flashed (check uname -v date)

Manual checks with spidev_test (run twice after power-up):
  spidev_test -D /dev/spidev1.0 -s 1000000 -v -p '\x80\x00\x00\x00'
      RX: 00 00 48 12   -> chip ID 0x48
  spidev_test -D /dev/spidev1.0 -s 1000000 -v -p '\x82\x00\x00\x00'
      RX: 00 00 01 00   -> STATUS 0x0001 (power-on detected)


HARDWARE
--------
  ECSPI1 (30820000.spi) -> /dev/spidev1.0
  module pin 100  SCK   GPIO5_IO06
  module pin  99  MOSI  GPIO5_IO07
  module pin  98  MISO  GPIO5_IO08
  module pin  97  CS    GPIO5_IO09 (cs-gpios, active low)

No BMI330 kernel driver exists in mainline 6.6 (BMI323 only), so the
sensor is driven from userspace through spidev.


BUILD (Yocto, meta-phytec-vm117)
--------------------------------
recipes-kernel/linux/linux-karo_%.bbappend stages:
  linux-karo/imx8mp-bmi330-spi.dtsi
      &ecspi1: pinctrl_ecspi1, cs-gpios <&gpio5 9 GPIO_ACTIVE_LOW>,
      spidev@0 compatible "rohm,dh2228fv", reg 0, 10 MHz max
      &iomuxc: ECSPI1 SCLK/MOSI/MISO 0x82, SS0 as GPIO5_IO09 0x40000
  linux-karo/bmi330-spi.cfg
      CONFIG_SPI=y, CONFIG_SPI_IMX=y, CONFIG_SPI_SPIDEV=y
      (Ka-Ro defconfig already sets these; no leading spaces in the
      file or Kconfig ignores the lines)

do_configure:append installs the dtsi into the kernel source and appends
#include "imx8mp-bmi330-spi.dtsi" to imx8mp-qsxp-ml81.dts (guarded so it
is added once). spidev is built in, so no kernel module package needed.

After changes rebuild and reflash both images:
  bitbake karo-image-bootfs karo-image-minimal
  cp -L the .ext4 files from tmp/deploy/images/qsxp-ml81 to ~/uuu-flash
